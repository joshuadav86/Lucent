# Windows and Mac parity

Lucent for Windows (`src/Lucent.Windows`) and Lucent for the Mac (`src/Lucent.Mac`) are meant to be the same app: every window, option, and feature on both. A new feature lands on both platforms in the same pull request. When it can't (the other platform has no way to do it, or it's being ported separately), it's listed here, with why and what the other platform has instead.

Every pull request runs `dotnet run --project tools/ParityCheck`, which checks three things and fails if one of them is on one platform without being listed in a table below:

1. Every source file in one app has its counterpart at the same place in the other. A WPF window's `.xaml` and `.xaml.cs` pair with an Avalonia window's `.axaml` and `.axaml.cs`.
2. Every setting in `Lucent.Core/Settings` is used by both apps.
3. Every public type in `Lucent.Core` that one app uses, the other uses too.

It also fails when an entry here is out of date, such as a file that's now on both platforms, so take an entry off the list when its gap closes. In the tables, the first column names files as each app has them (under its own folder), settings, or `Lucent.Core` types, in `code`; the second says which app has them. Rows without `code` are notes the check doesn't read.

## Features on one platform

| What | Only on | Why, and what the other platform has |
| --- | --- | --- |
| MusicBee import button | Windows | MusicBee is Windows-only. On a Mac, the Apple Music import takes a MusicBee library file too. |
| Apple Music's playlists in the library under PLAYLISTS | Mac | Spotify's playlists are listed on both, through its Web API. The Mac also lists the Music app's playlists (while Music is open) through AppleScript. Windows' Apple Music app has no way for other apps to read its playlists. YouTube, TIDAL, SoundCloud, and Pandora don't share playlists with Lucent (YouTube and TIDAL only with apps they've approved, SoundCloud takes no new apps, Pandora has no public API), so they aren't listed on either; while one is controlled, PLAYLISTS says why under its name (`IRemotePlayer.PlaylistsLimit`). An opened playlist's columns work the same on both; the Music app's songs also fill Genre. |
| "Play on this Mac" for Apple Music on AirPlay speakers, through `IRemoteDevices` | Mac | Spotify Connect's "Play on this Mac/PC" works on both, through its Web API. The Mac's Music app says through AppleScript which AirPlay speakers it plays on and can be moved back to the Mac. Windows' Apple Music app tells other apps nothing about AirPlay. |

## Same feature, different platform pieces

Each platform does these its own way. The feature is on both; only the files differ.

| What | Only on | Its counterpart on the other platform |
| --- | --- | --- |
| Drawing the visuals: `Visualizer/Renderer.cs`, `Visualizer/Renderer.Offscreen.cs`, `Visualizer/ShaderCache.cs`, `Visualizer/PresetLibrary.cs`, `Visualizer/MilkDrop/MilkDropRenderer.cs`, `Visualizer/MilkDrop/MilkDropVisual.cs` | Windows | Direct3D 11 with HLSL compiled as it loads. The Mac draws the same visuals with Metal: `Visuals/` (shaders translated from the HLSL when the app is built, and by DXC as it runs for your own visuals). |
| Drawing the visuals with Metal: `Visuals/MetalRenderer.cs`, `Visuals/MetalView.cs`, `Visuals/VisualEngine.cs`, `Visuals/MetalSupport.cs`, `Visuals/MetalTranslation.cs`, `Visuals/MetalShaderFiles.cs`, `Visuals/ShaderCache.cs`, `Visuals/DxcCompiler.cs`, `Visuals/MetalPipelines.cs`, `Visuals/MilkDropRenderer.cs`, `Visuals/MilkDropVisual.cs`, `Visuals/VisualEngine.Offscreen.cs` | Mac | Windows' `Visualizer/Renderer.cs` and friends. |
| The library's store headings and folder subheadings: `Windows/FolderGroupStyleSelector.cs` | Windows | WPF picks each group's look with a style selector. The Mac lays out its heading and subheading rows itself in `Library/LibraryRows.cs`. |
| Exclusive (bit-perfect) output through WASAPI: `Audio/PcmOutput.cs` | Windows | WASAPI exclusive mode is Windows-only. The Mac does the same with Core Audio: `Audio/ExclusiveDevice.cs` takes the device in hog mode (other apps go quiet) and switches it to each track's own sample rate. |
| Exclusive (bit-perfect) output through Core Audio: `Audio/ExclusiveDevice.cs` | Mac | Windows' `Audio/PcmOutput.cs`, through WASAPI exclusive mode. |
| Playing sound through Core Audio: `Audio/AudioQueueOutput.cs`, `Audio/MacAudioFileReader.cs`, `Interop/CoreAudio.cs` | Mac | Windows plays through WASAPI (NAudio, and `Audio/PcmOutput.cs` for exclusive mode) and decodes with Media Foundation and NAudio. The Mac decodes the same formats with macOS's own decoders (Extended Audio File Services). |
| Handing recorded frames to the encoder: `Export/VideoFrameConverter.cs` | Windows | Windows converts each frame to NV12 on the graphics card for Media Foundation. The Mac reads each frame back from Metal into AVFoundation's pixel buffers: `Export/VideoFrameReader.cs`. |
| Handing recorded frames to the encoder: `Export/VideoFrameReader.cs` | Mac | Windows' `Export/VideoFrameConverter.cs`. |
| macOS interop: `Interop/ObjC.cs`, `Interop/AppKit.cs`, `Interop/CoreGraphics.cs`, `Interop/StringHelper.cs`, `Interop/WebKit.cs`, `Interop/Keychain.cs`, `Interop/AVFoundation.cs`, `Interop/CoreMedia.cs`, `Interop/AudioTap.cs` | Mac | WPF and Windows' own APIs. The Bandcamp and Spotify sign-ins use the keychain on a Mac, DPAPI on Windows. Listening to other apps uses a Core Audio process tap on a Mac (`Interop/AudioTap.cs`), NAudio's WASAPI loopback on Windows. |
| Listening to other apps' sound (Audio/SystemAudio.cs, on both) | Both | Windows listens through WASAPI loopback on the default output; music Lucent plays in exclusive mode skips Windows' mixer, so loopback can't hear it. The Mac uses a Core Audio process tap, which needs macOS 14.2 or later and the user's OK under "System Audio Recording Only" (the menu item is greyed out on older macOS). While Lucent controls an app, both listen to that app alone: Windows through process loopback on the app's process and those it started (Windows 10 version 2004 and later; older Windows hears every app), the Mac through a tap of the processes whose bundle IDs are the app's. Both start listening again by themselves when the default output changes (Windows through an endpoint notification, the Mac through a property listener), when starting failed, and when the controlled app says it's playing here while nothing has been heard for 5 seconds (Lucent.Core's `Audio/ListeningWatchdog.cs`, backing off to once a minute while it stays silent). |
| Controlling Apple Music (Streaming/AppleMusicRemote.cs, on both) | Both | Apple's MusicKit only works on Apple's platforms and plays inside the app using it, so neither app uses it. Windows reads and presses the Apple Music app's (or iTunes') buttons through Windows' media controls. The Mac drives the Music app with AppleScript, after the user allows it under Automation. Neither needs an Apple sign-in. |
| Shaping the controlled streaming app's sound with the equalizer: `Audio/EqualizerApo.cs` | Windows | Both shape it only when "EQ streaming apps too" is on in Options › Sound. Windows can't quieten another app and play its sound itself, so it hands the equalizer's curve to Equalizer APO (installed separately; the equalizer window offers its download page), which shapes everything on the outputs it's installed on while an app is in control. The Mac does it itself in `Audio/SystemAudio.cs`: a tap of just the app that macOS quietens once it hears the app, played back through a copy of the equalizer on the tap's own device. |
| Being the default music and video player: `Library/FileAssociations.cs` | Windows | Windows lists Lucent in Default apps from the registry and has people choose it there. The Mac declares its music and video types in Info.plist (`tools/mac/package-mac.sh`) and sets itself as their default with `Interop/LaunchServices.cs`: since macOS asks the user to confirm each type, the common music types by default and every type from a second button. Both ask their system afterwards what each type opens in, and Options says (`Library/DefaultPlayerStatus.cs`). |
| Being the default music player: `Interop/LaunchServices.cs` | Mac | Windows' `Library/FileAssociations.cs`. |
| Songs opened while Lucent is running: `Library/OpenRequests.cs` | Windows | Windows starts a second Lucent for each song opened from Explorer, so it hands the song to the running one over a pipe. macOS sends songs to the running Lucent itself (`App.axaml.cs`). |
| Controlling YouTube in a browser (Streaming/YouTubeRemote.cs, on both) | Both | Windows reads and presses the browser's buttons through Windows' media controls, which Chrome, Edge, Firefox and the rest already report every site to, so nothing needs turning on. Windows doesn't say which site a browser is playing, so Windows has one item, "Control your web browser", for YouTube, SoundCloud, TIDAL's web player and any other site. macOS has no media controls other apps may press, so the Mac finds the site's tab in Safari, Chrome, Edge or Brave with AppleScript and runs JavaScript in it, with an item for each site it knows: YouTube, TIDAL's web player and SoundCloud. That needs the browser's "Allow JavaScript from Apple Events" turned on, and the user's OK under Automation. Firefox and Arc can't run JavaScript for AppleScript, so the Mac can't control sites in them. |
| Controlling sites in a browser by their tabs: `Streaming/BrowserTabRemote.cs`, `Streaming/SoundCloudRemote.cs` | Mac | What the Mac's YouTube, TIDAL and SoundCloud control share, and SoundCloud's own player bar. Windows controls SoundCloud with its browser item (`Streaming/YouTubeRemote.cs`), through Windows' media controls. SoundCloud's "Next up" isn't read on either (the queue window says why). The Mac also presses SoundCloud's, TIDAL's, YouTube Music's and a YouTube playlist's own shuffle and repeat buttons (YouTube loops the video); Windows can only use shuffle and repeat where an app offers them to Windows' media controls, which browsers don't. |
| Controlling TIDAL (Streaming/TidalRemote.cs, on both) | Both | Windows reads and presses the TIDAL app's buttons through Windows' media controls. TIDAL's Mac app can't be controlled by other apps (no AppleScript, and macOS keeps its Now Playing to itself), so the Mac controls TIDAL's web player (tidal.com) in a browser tab instead. TIDAL's play queue isn't read on either; the queue window says why. |
| Controlling Pandora (Streaming/PandoraRemote.cs, on both) | Both | Pandora has no public API on either. Pandora's Windows app doesn't tell Windows' media controls anything, so Windows reads Pandora's window with UI Automation (the song, its times, and the play, skip, replay and thumbs buttons) and presses its buttons there; for pandora.com in a browser, the browser's media controls give the song and cover too. A browser only shows UI Automation the tab in front, so a Pandora tab is read while it's the one showing. Pandora has no Mac app, so the Mac controls the web player (pandora.com) in a browser tab, thumbs included. Stations can't go back or seek on either, and the free tier's skip limit holds. |
| Opening the controlled app from the player (Streaming/AppOpener.cs, on both) | Both | When the app Lucent controls isn't open and nothing is playing, the player shows an Open button in the volume bar's place; it starts the app, waits for it, then presses again the button that didn't work. Windows starts Spotify, TIDAL, Apple Music and Pandora by their links, their installers' places or their Microsoft Store packages, and opens pandora.com when Pandora's app isn't installed. The Mac starts Spotify and Music with `open`, and opens Pandora, YouTube, TIDAL and SoundCloud's sites in a browser Lucent can reach. Windows' browser item names no site, so it has no Open button. |
| Recording from an audio interface (Audio/LiveInputs.cs and RecordWindow, on both) | Both | Windows records through WASAPI, at the rate set for the device in Windows' Sound settings (Lucent converts it to the rate chosen), or through the interface's ASIO driver, which runs at the chosen rate with the lowest delay. Macs have no ASIO: Core Audio already talks to interfaces directly, so the Mac switches the interface to the chosen rate itself and records through an Audio Queue. The Mac asks once for permission to use inputs (Privacy & Security, Microphone). |
| Other apps' players through Windows' media controls: `Streaming/MediaControlsRemote.cs` | Windows | What Windows' Apple Music, TIDAL and browser control share, including the volume bar, which sets the app's volume in Windows' volume mixer. On a Mac the bar sets Music's own volume, and YouTube's or TIDAL's player's in the tab; SoundCloud's isn't reachable, so the bar hides for it. Spotify's volume is set on whichever device it plays on, through its Web API, on both; while Spotify has asked Lucent to wait (or the account isn't Premium) and it plays on this computer, the bar stays and sets Spotify here instead (its own slider on a Mac, its volume mixer level on Windows). The Mac reaches the Music app and browsers with AppleScript, in each one's own file. |
| Hearing the controlled app change songs: `Streaming/AppAnnouncements.cs` | Mac | Both show a new song the moment the app announces it (`IRemoteNotifier`, in Lucent.Core's Streaming/RemotePlayer.cs). Windows hears it from Windows' media controls, in `Streaming/MediaControlsRemote.cs`, for every app controlled through them. The Mac listens for Spotify's and Music's announcements to the whole Mac (distributed notifications) in this file. Sites in browser tabs announce nothing on a Mac, so they're still read every second. |
| Apple Music's and YouTube's own lists, through `IRemoteLists` (in Lucent.Core's Streaming/RemotePlayer.cs) | Mac | The queue window shows the playlist the other app is playing through, on both. Spotify's playlist, album, Liked Songs or Up next comes from its Web API in Lucent.Core, so it's the same on both. Windows' media controls only tell other apps the song playing, not what it's playing from, so on Windows the queue window says so while it controls Apple Music, TIDAL, Pandora or a browser (`IRemotePlayer.ListLimit`). The Mac reads the Music app's current playlist with AppleScript, a YouTube playlist from the panel beside the video, and YouTube Music's queue. |
| Songs' own web links, through `IRemoteLinks` (in Lucent.Core's Streaming/RemotePlayer.cs) | Mac | Share, Copy song link, works for every controlled app on both. Spotify's link comes from its Web API on both. The Mac also knows YouTube's, TIDAL's and SoundCloud's links from their tabs. Windows' media controls only give a song's title and artist, so Windows (and the Mac, for Apple Music) finds the song on Apple Music through Apple's public search and shares that link, or its song.link page from apps other than Apple Music (`SongLinks`). Add to playlist works with Spotify on both, and with the Music app's playlists on a Mac through AppleScript. Apple Music's Windows app has no way for other apps to reach its playlists, so its Add to playlist says why instead of listing playlists, as it does for every app that can't add songs. |
| The menu bar: `Player/MainWindow.MenuBar.cs` | Mac | Macs have one menu bar at the top of the screen. Windows has the same commands in the player's right-click menu and keyboard shortcuts. |
| WPF stand-ins for Avalonia: `Windows/MessageWindow.axaml`, `Windows/MessageWindow.axaml.cs`, `Windows/Placement.cs`, `Windows/ResourceReferences.cs`, `Windows/Chrome.cs`, `Library/LibraryRows.cs`, `Editor/EditorFonts.cs`, `Editor/AudioClipboard.cs` | Mac | What WPF has built in: MessageBox, window bounds, SetResourceReference, WindowChrome, grouped lists, Consolas, and Clipboard.SetAudio. |
| Menus kept clear of the taskbar: `Windows/DropDownMenu.cs` | Windows | Avalonia's menus keep themselves on screen and clear of the Dock. |
| Corners that fit their shape: `Windows/RoundedBorder.cs` | Windows | WPF draws a corner radius bigger than half a border's height as an oval, so pills and switches came out as ellipses. Avalonia shrinks oversized corners to fit by itself, as CSS does, so the Mac's pills are already round-ended. |
| The self-test's sound checks and visual timing: `Diagnostics/SelfTest.Sound.cs`, `Diagnostics/SelfTest.Timing.cs` | Mac | Kept in their own files on the Mac. Windows' self-test doesn't check gapless or the outputs yet, and doesn't time the visuals: the slow ones turned up on Retina Macs. |
| Screenshot tool: `Diagnostics/Screenshots.cs`, `Diagnostics/Screenshots.TrackInfo.cs`, `Diagnostics/Screenshots.Desk.cs`, `Diagnostics/Screenshots.Clip.cs`, `Player/MainWindow.Preview.cs`, `Player/AnalyzerSampleMusic.cs`, `Diagnostics/LayoutCheck.cs` | Mac | `Lucent --screenshots` draws the Mac windows on any OS (Linux included) for checking them by eye, and the layout check runs in CI. Windows' windows are checked on Windows. |
| `MilkTranslatedShader` | Mac | Both apps translate MilkDrop shaders with `MilkShaderTranslator`, but only the Mac's code names the result's type. |
